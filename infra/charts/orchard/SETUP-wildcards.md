# Orchard chart: wildcard certs + Gateway as templates

Design notes from when the raw Gateway manifests moved into the chart and it gained declarative wildcard `Certificate` resources, parameterised through `values.yaml`. That work has shipped, so read this as history; [README.md](README.md) has the current values. A DNS-01 `ClusterIssuer` is what makes issuance work, and setting one up is outside this chart.

## Goal

Make Orchard fully deployment-agnostic on the TLS / Gateway side:

- One image per release, one chart per release, zero hardcoded domains.
- Operators set `values.yaml` for their cluster and everything wires up.
- Wildcard certs (`*.k.hackclub.dev`, `*.a.db.tier2.infra.hackclub.com`, etc.) are issued **automatically** by cert-manager against the `letsencrypt-dns01-wildcard` ClusterIssuer.
- Gateway listeners + cert references come from values.

Backward-compatible: an operator running the chart with no new values gets the previous defaults (`a.lfdl.ink`, `db.orchard.my`, etc.).

## Scope of changes

| Area | What | Where |
|---|---|---|
| `values.yaml` | Add `certificates` + `gateway` blocks | `charts/orchard/values.yaml` |
| Cert templates | Render `cert-manager.io/v1 Certificate` per enabled wildcard | `charts/orchard/templates/certificates.yaml` (NEW) |
| Gateway template | Move the raw Gateway + listener config in here | `charts/orchard/templates/gateway.yaml` (NEW) |
| Remove raw manifests | Delete now-redundant files | `k8s/gateway-api/00-cert-wildcard-a-lfdl-ink.yaml`, `k8s/gateway-api/10-http-gateway.yaml` |
| Server code | Env-ify the one remaining hardcoded TLS secret name | `server/src/kubernetes/kubernetes.service.ts:5597–5600` |
| Server deployment env | New env var so each cluster passes its own secret names | `charts/orchard/templates/server.yaml` (env block) + `values.yaml` |
| Docs | Append a new section to `README.md` | `charts/orchard/README.md` |

There is **no** cert change needed for `*.a.pub.tier2.infra.hackclub.com` — the public-deployment domain is TCP/UDP passthrough via MetalLB. No TLS termination happens at the cluster, so no cert resource lives in this chart for it. Operators terminating TLS in front of that LB (e.g. a separate proxy) handle their own cert there.

## File-by-file changes

### 1. `charts/orchard/values.yaml` — additions

Append. Keep existing blocks intact.

```yaml
# ── Gateway API HTTP gateway ──
# Shared L7 gateway for app HTTP/HTTPS. Replaces the raw manifest that used to
# live under k8s/gateway-api/10-http-gateway.yaml. Disable if your cluster
# uses a non-Gateway-API ingress and you wire routing some other way.
gateway:
  enabled: true
  name: http-gateway
  namespace: network          # where the Gateway lives; cert Secrets must be readable here
  gatewayClassName: traefik
  # The hostname pattern for autogenerated app domains. Must align with
  # APP_DOMAIN / PUBLIC_APP_DOMAIN on server + frontend.
  appDomain: a.lfdl.ink
  # Secret holding the wildcard cert covering *.{appDomain}. Either:
  #   - issued by certificates.wildcards.app below (chart-managed), or
  #   - pre-existing in {namespace} (set certificates.wildcards.app.enabled: false)
  appWildcardSecretName: wildcard-a-lfdl-ink-tls

# ── cert-manager Certificates for cluster wildcards ──
# Requires cert-manager + a working DNS-01 ClusterIssuer (see the acme-dns
# spec in the kubeops repo). Set enabled=false if you provision certs another
# way and just want the chart to consume pre-existing Secrets.
certificates:
  enabled: true
  namespace: network          # where the Certificates + their Secrets live
  issuer:
    name: letsencrypt-dns01-wildcard
    kind: ClusterIssuer
  duration: 2160h             # 90d
  renewBefore: 360h           # 15d
  privateKey:
    algorithm: ECDSA
    size: 256
    rotationPolicy: Always
  wildcards:
    # *.{gateway.appDomain} — terminates TLS on the shared HTTP gateway.
    app:
      enabled: true
      # Defaults derive from gateway.appDomain; override only to decouple.
      domain: ""              # empty → {{ .Values.gateway.appDomain }}
      secretName: ""          # empty → {{ .Values.gateway.appWildcardSecretName }}
    # *.{db.domain} — used by the server's syncPublicTlsSecret() to copy
    # cert-manager wildcard into project namespaces for CNPG TLS.
    db:
      enabled: true
      domain: db.orchard.my
      secretName: wildcard-db-orchard-my-tls

# ── Public-TLS reflection secrets (server reads these from env) ──
# Tells the server which Secret in {certificates.namespace} to copy from when
# exposing a CNPG cluster publicly with TLS. The server already reads
# PUBLIC_DB_DOMAIN; this adds the secret-name override that was previously
# hardcoded in kubernetes.service.ts.
publicTls:
  db:
    sourceNamespace: ""       # empty → {{ .Values.certificates.namespace }}
    sourceSecret: ""          # empty → {{ .Values.certificates.wildcards.db.secretName }}
    localSecret: wildcard-db-tls
```

### 2. `charts/orchard/templates/certificates.yaml` — new file

```yaml
{{- if .Values.certificates.enabled }}
{{- $issuer := .Values.certificates.issuer -}}
{{- $ns := .Values.certificates.namespace -}}
{{- $defaults := dict "duration" .Values.certificates.duration "renewBefore" .Values.certificates.renewBefore "privateKey" .Values.certificates.privateKey -}}

{{- /* App wildcard */ -}}
{{- with .Values.certificates.wildcards.app }}
{{- if .enabled }}
{{- $domain := .domain | default $.Values.gateway.appDomain -}}
{{- $secret := .secretName | default $.Values.gateway.appWildcardSecretName -}}
---
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: {{ $secret }}
  namespace: {{ $ns }}
  labels: {{- include "orchard.labels" $ | nindent 4 }}
spec:
  secretName: {{ $secret }}
  issuerRef:
    name: {{ $issuer.name }}
    kind: {{ $issuer.kind }}
  commonName: "*.{{ $domain }}"
  dnsNames:
    - "*.{{ $domain }}"
    - "{{ $domain }}"
  privateKey: {{- toYaml $defaults.privateKey | nindent 4 }}
  duration: {{ $defaults.duration }}
  renewBefore: {{ $defaults.renewBefore }}
{{- end }}
{{- end }}

{{- /* DB wildcard */ -}}
{{- with .Values.certificates.wildcards.db }}
{{- if .enabled }}
---
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: {{ .secretName }}
  namespace: {{ $ns }}
  labels: {{- include "orchard.labels" $ | nindent 4 }}
spec:
  secretName: {{ .secretName }}
  issuerRef:
    name: {{ $issuer.name }}
    kind: {{ $issuer.kind }}
  commonName: "*.{{ .domain }}"
  dnsNames:
    - "*.{{ .domain }}"
    - "{{ .domain }}"
  privateKey: {{- toYaml $defaults.privateKey | nindent 4 }}
  duration: {{ $defaults.duration }}
  renewBefore: {{ $defaults.renewBefore }}
{{- end }}
{{- end }}
{{- end }}
```

`include "orchard.labels"` should be the existing helpers label template in `_helpers.tpl`. If it doesn't exist under that name, replace with whatever the chart's standard label helper is — check `_helpers.tpl`.

### 3. `charts/orchard/templates/gateway.yaml` — new file

Mirrors the raw manifest at `k8s/gateway-api/10-http-gateway.yaml` but parameterised. The TLS secret name is now derived from values, not hardcoded.

```yaml
{{- if .Values.gateway.enabled }}
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: {{ .Values.gateway.name }}
  namespace: {{ .Values.gateway.namespace }}
  labels:
    {{- include "orchard.labels" . | nindent 4 }}
    leaf.dev/managed: "true"
    leaf.dev/role: http
spec:
  gatewayClassName: {{ .Values.gateway.gatewayClassName }}
  listeners:
    - name: http
      protocol: HTTP
      port: 80
      allowedRoutes:
        namespaces:
          from: All
    - name: https-wildcard
      protocol: HTTPS
      port: 443
      hostname: "*.{{ .Values.gateway.appDomain }}"
      tls:
        mode: Terminate
        certificateRefs:
          - kind: Secret
            group: ""
            name: {{ .Values.gateway.appWildcardSecretName }}
      allowedRoutes:
        namespaces:
          from: All
{{- end }}
```

Custom-domain HTTPS listeners are still appended to this Gateway at runtime by the server (`KubernetesService.ensureCustomDomainListener`) — leave that path alone.

### 5. Server code — env-ify the last hardcoded TLS secret

`server/src/kubernetes/kubernetes.service.ts:5595–5600` currently:

```ts
private readonly PUBLIC_TLS_SOURCE_NAMESPACE = 'network';
private readonly PUBLIC_TLS_SOURCE_SECRET = 'wildcard-db-orchard-my-tls';
private readonly PUBLIC_TLS_BASE_DOMAIN = process.env.PUBLIC_DB_DOMAIN || 'db.orchard.my';
private readonly PUBLIC_TLS_LOCAL_SECRET = 'wildcard-db-tls';
```

Change to:

```ts
private readonly PUBLIC_TLS_SOURCE_NAMESPACE = process.env.PUBLIC_DB_TLS_SOURCE_NAMESPACE || 'network';
private readonly PUBLIC_TLS_SOURCE_SECRET   = process.env.PUBLIC_DB_TLS_SOURCE_SECRET   || 'wildcard-db-orchard-my-tls';
private readonly PUBLIC_TLS_BASE_DOMAIN     = process.env.PUBLIC_DB_DOMAIN              || 'db.orchard.my';
private readonly PUBLIC_TLS_LOCAL_SECRET    = process.env.PUBLIC_DB_TLS_LOCAL_SECRET    || 'wildcard-db-tls';
```

All four defaults match prior behavior, so existing deployments are unaffected if the env vars are unset.

### 6. Server deployment template — wire the env

In `charts/orchard/templates/server.yaml` find the `env:` block for the `server` container. Append:

```yaml
{{- if .Values.publicTls.db }}
- name: PUBLIC_DB_TLS_SOURCE_NAMESPACE
  value: {{ .Values.publicTls.db.sourceNamespace | default .Values.certificates.namespace | quote }}
- name: PUBLIC_DB_TLS_SOURCE_SECRET
  value: {{ .Values.publicTls.db.sourceSecret | default .Values.certificates.wildcards.db.secretName | quote }}
- name: PUBLIC_DB_TLS_LOCAL_SECRET
  value: {{ .Values.publicTls.db.localSecret | quote }}
{{- end }}
```

The existing `PUBLIC_DB_DOMAIN`, `APP_DOMAIN`, `INGRESS_CNAME`, `PUBLIC_DEPLOYMENT_DOMAIN` env vars stay as they are.

### 7. `charts/orchard/README.md`: new section

Append after section 4 ("Full values reference"):

````markdown
### Certificates (`certificates.*`)

| Key | Default | Description |
|---|---|---|
| `certificates.enabled` | `true` | Render `cert-manager.io/v1 Certificate` resources for the configured wildcards. Set `false` if you pre-provision Secrets out-of-band. |
| `certificates.namespace` | `network` | Namespace where Certificates + their Secrets live. The Gateway in `gateway.namespace` must be able to read Secrets here (same namespace = simplest). |
| `certificates.issuer.name` | `letsencrypt-dns01-wildcard` | Name of the `ClusterIssuer` (or `Issuer`) used to issue. **Must support DNS-01 challenges** — install acme-dns (see kubeops repo) or another DNS-01 path before enabling. |
| `certificates.issuer.kind` | `ClusterIssuer` | `ClusterIssuer` or `Issuer`. |
| `certificates.wildcards.app.enabled` | `true` | Issue the wildcard cert for autogen app domains. |
| `certificates.wildcards.app.domain` | `""` (→ `gateway.appDomain`) | The hostname pattern. The cert will cover `*.{domain}` + `{domain}`. |
| `certificates.wildcards.app.secretName` | `""` (→ `gateway.appWildcardSecretName`) | Secret name to write the cert into. Same name is consumed by the Gateway listener. |
| `certificates.wildcards.db.enabled` | `true` | Issue the wildcard cert for public DB exposure. |
| `certificates.wildcards.db.domain` | `db.orchard.my` | Hostname pattern for CNPG public exposure. Matches `server.env.PUBLIC_DB_DOMAIN`. |
| `certificates.wildcards.db.secretName` | `wildcard-db-orchard-my-tls` | Secret consumed by the server's TLS reflection (`syncPublicTlsSecret`). |

### Gateway (`gateway.*`)

| Key | Default | Description |
|---|---|---|
| `gateway.enabled` | `true` | Render the shared L7 Gateway API `Gateway` for HTTP/HTTPS routes. Disable if you wire routing via Traefik IngressRoute exclusively. |
| `gateway.name` | `http-gateway` | Gateway object name. The server (`ensureCustomDomainListener`) targets this name when appending custom-domain listeners — keep in sync. |
| `gateway.namespace` | `network` | Namespace the Gateway lives in. |
| `gateway.gatewayClassName` | `traefik` | `GatewayClass` to attach to. |
| `gateway.appDomain` | `a.lfdl.ink` | Hostname pattern for autogenerated user app domains (e.g. `<rand>.{appDomain}`). Must match server `APP_DOMAIN` and frontend `PUBLIC_APP_DOMAIN`. |
| `gateway.appWildcardSecretName` | `wildcard-a-lfdl-ink-tls` | Secret holding the wildcard TLS cert for `*.{appDomain}`. Defaults match the chart-managed `Certificate` above. |

### Public TLS reflection (`publicTls.*`)

| Key | Default | Description |
|---|---|---|
| `publicTls.db.sourceNamespace` | `""` (→ `certificates.namespace`) | Where the server reads the wildcard DB cert FROM. Sets `PUBLIC_DB_TLS_SOURCE_NAMESPACE`. |
| `publicTls.db.sourceSecret` | `""` (→ `certificates.wildcards.db.secretName`) | Secret name to copy. Sets `PUBLIC_DB_TLS_SOURCE_SECRET`. |
| `publicTls.db.localSecret` | `wildcard-db-tls` | Name written into each project namespace where a CNPG cluster needs TLS. Sets `PUBLIC_DB_TLS_LOCAL_SECRET`. |
````

## tier2 example override

Concrete values for a `tier2.infra.hackclub.{dev,com}` deploy (after the acme-dns SETUP.md is implemented and `letsencrypt-dns01-wildcard` exists in the cluster):

```yaml
gateway:
  http:
    appDomain: k.hackclub.dev
    appWildcardSecretName: wildcard-k-hackclub-dev-tls

certificates:
  enabled: true
  issuer:
    name: letsencrypt-dns01-wildcard
  wildcards:
    app:
      enabled: true
      # leaves domain/secretName empty → inherits from gateway.* above
    db:
      enabled: true
      domain: a.db.tier2.infra.hackclub.com
      secretName: wildcard-db-tier2-tls

publicTls:
  db:
    sourceSecret: wildcard-db-tier2-tls
    localSecret: wildcard-db-tls   # stays the same — only the source changes

server:
  env:
    - { name: APP_DOMAIN,                value: k.hackclub.dev }
    - { name: INGRESS_CNAME,             value: a.ingress.tier2.infra.hackclub.com }
    - { name: PUBLIC_DB_DOMAIN,          value: a.db.tier2.infra.hackclub.com }
    - { name: PUBLIC_DEPLOYMENT_DOMAIN,  value: a.pub.tier2.infra.hackclub.com }

frontend:
  env:
    - { name: PUBLIC_APP_DOMAIN,         value: k.hackclub.dev }
    - { name: PUBLIC_INGRESS_CNAME,      value: a.ingress.tier2.infra.hackclub.com }
    - { name: PUBLIC_DEPLOYMENT_DOMAIN,  value: a.pub.tier2.infra.hackclub.com }
```

A vanilla `helm install` with no overrides keeps the previous `orchard.my` / `a.lfdl.ink` behavior (only difference: the certs are now chart-managed instead of dropped in from the raw `k8s/gateway-api/` directory).

## Migration notes

- Operators currently on `a.lfdl.ink` / `db.orchard.my` need no values changes; defaults preserve current behavior. The only externally-visible change is the cert + Gateway resources now show `app.kubernetes.io/managed-by: Helm` instead of being unmanaged.
- If a cluster previously had the raw `k8s/gateway-api/` Certificate applied manually, `helm install` will try to take ownership. Either:
  - Delete the existing Certificate first (the issued Secret survives), then install — cert-manager re-issues but the Secret keeps the same name and same Gateway picks it back up, or
  - Annotate the existing resources `meta.helm.sh/release-name=orchard` + `meta.helm.sh/release-namespace=<ns>` and label `app.kubernetes.io/managed-by=Helm`, then helm adopts them.
