A database in Orchard is a managed Postgres instance in a project. Orchard runs it as a CloudNativePG cluster. CloudNativePG is the Kubernetes operator that handles failover, storage, and backups.

## Create a database

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

1. Open a project.
2. Select **New app**.
3. In **Start from scratch**, select **Postgres**.
4. In **Start from**, keep **Empty**. You can also select **Import from URL** or **Copy of a database**.
5. In **Database name**, enter a name.
6. In **Postgres version**, select a version.
7. In **Storage size**, set the volume size. The default is 1 GiB.
8. In **Resources**, set the CPU, memory, and **Instances**.
9. Select **Create database**.

</TabItem>
<TabItem label="CLI">

```sh
orchard db create --name appdb --pg-major 17 --storage 10Gi --wait
```

To seed the database from another Postgres server, add `--restore-from postgres://...`.

</TabItem>
</Tabs>

## Connect an app

To connect an app in the same project, use a reference. A reference follows the database through a password rotation or a restore.

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

1. Open the app.
2. Go to **Variables**.
3. Add a variable named `DATABASE_URL`.
4. In the value field, select **Use a resource**.
5. Select the database.
6. Select **Save**.

</TabItem>
<TabItem label="CLI">

```sh
orchard deploy bindings add <app-id> --database appdb
```

</TabItem>
</Tabs>

### Get a connection string

1. Open the database.
2. Select **Connect**.
3. Select **Private** to connect from apps in this project, or **Public** to connect from anywhere.
4. Select a format: **URI**, **psql**, **.env**, or **JDBC**.
5. For a private connection, select the instances: **Primary**, **Standbys**, or **Any**.

The private host is a cluster-internal address, such as `pg-<name>-rw.<namespace>.svc.cluster.local`. Traffic to it stays inside the cluster. Apps in the same project use this address.

To print the connection details from the CLI, run `orchard db connection <id>`. To open a `psql` session, run `orchard db psql <id>`.

## Set CPU and memory

Set CPU and memory under **Settings** > **Resources**, or with `orchard db resources set <id>`.

Orchard sizes `shared_buffers` and backup compression from the memory limit, and recalculates them when the memory changes. To set `shared_buffers` yourself, refer to [Change Postgres parameters](/data/parameters/#shared-buffers).

:::caution
Postgres reserves `shared_buffers` when it starts. If this value is close to the memory limit, connections and backups have no room in the container, and the kernel can kill Postgres.
:::

## Public access

By default, only apps in the project can connect. Public access assigns a port on the organization's public IP address, so you can connect from your computer or a business intelligence tool.

### Prerequisites

- A layer 4 (L4) load balancer in the cluster.
- A public IP address. To set one for your organization, go to **Organization settings** > **Database defaults** > **Public database IP**. Otherwise, the organization inherits the instance default.

Public access is not available in Cloudflare Tunnel mode, because tunnels carry HTTP only.

### Turn on public access

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

1. Open the database.
2. Go to **Settings** > **Public access**.
3. Turn on **Reachable from the internet**.

</TabItem>
<TabItem label="CLI">

```sh
orchard db public enable <id>
```

</TabItem>
</Tabs>

:::caution
Anyone with the password can connect to a public database. Use a strong password, and turn off public access when you finish. To change the password, run `orchard db rotate-password <id>`.
:::

## Delete a database

Deleting a database moves it to **Recently deleted** on the project for 30 days. You can bring it back only if it had at least one completed backup. For the steps, refer to [Recover a deleted database](/data/backups/#recover-a-deleted-database).

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

1. Open the database.
2. Go to **Settings** > **Danger zone**.
3. Select **Delete database**.
4. Confirm the deletion.

</TabItem>
<TabItem label="CLI">

```sh
orchard db delete <id>
```

</TabItem>
</Tabs>

:::caution
Orchard cannot delete a database while an app still references it. Remove the reference first.
:::
