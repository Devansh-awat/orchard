Orchard pauses writes when a database volume is nearly full, so grow the volume before that happens. Orchard grows the volume of every instance without a restart. You cannot decrease the size later, so grow it only as far as you need.

The largest volume is 200 GiB by default. An operator can change this limit under **Instance admin** > **Limits** > **Largest volume**, or with `MAX_VOLUME_SIZE`.

## Prerequisites

- Edit access to the project: the Admin or Member [project role](/teams/organizations/#project-roles).
- A dedicated database.

## Grow the volume

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

1. Open the database.
2. Go to **Settings** > **Resources**.
3. In **Storage**, increase **Size**.
4. Select **Grow to `<size>`**.
5. Select **Grow storage**.

The volume of every instance grows to the new size.

</TabItem>
<TabItem label="CLI">

```sh
orchard db storage expand <id> --size 20Gi
```

</TabItem>
</Tabs>

## Resume paused writes

Orchard pauses writes when the volume reaches 92% full. Reads continue. The **Storage** card shows `Writes are paused because the volume is full`.

To resume writes:

1. Grow the volume. The **Storage** card shows the minimum size.
2. Wait for the volume to drop under 85% full. Writes resume automatically.

The events **Writes paused (disk full)** and **Writes resumed** are available as [notifications](/run/notifications/).

## WAL archiving failures

If write-ahead log (WAL) archiving fails, WAL files continue to fill the volume. The **Storage** card shows `WAL archiving is failing`. Growing the volume adds time, but it does not fix the cause. To resolve the failure, check the [backup storage](/data/backups/#prerequisites) configuration.
