Orchard reads instance settings from environment variables, chart values, and the database. An environment variable always takes precedence over a value stored in the database.

## Environment variables

The server reads environment variables at boot. These cover the database URL, registry, app domain, cluster access, object storage, and email. For the full list, refer to the [configuration reference](/reference/configuration/).

To change a variable on an installer host, use [`orchardctl env`](/operate/host-commands/#env):

```bash
sudo orchardctl env set SMTP_HOST smtp.example.com --apply
```

On a Helm install, set the variable in `server.env` in your values file.

## Chart values

Chart values control what the chart deploys, such as metrics, logs, and the MCP server.

On an installer host, the values file is `/etc/orchard/values.yaml`. To change a value, use [`orchardctl config`](/operate/host-commands/#config):

```bash
sudo orchardctl config set logs.retention 30d --apply
```

On a Helm install, change your values file and run `helm upgrade`.

Re-running the installer keeps your secrets, custom environment variables, and volume sizes. It writes the other chart values again, so a value such as `signupMode` goes back to what the installer sets. To change one setting, use the commands in [Change settings that Instance admin cannot edit](#change-settings-that-instance-admin-cannot-edit).

Set cluster-specific values, such as storage class, ingress class, and registry, in the values file. These values differ for each cluster.

## Settings stored in the database

To change settings without a restart, go to **Instance admin** > **Configuration**. This page has the following sections:

- **Object storage**
- **Email**
- **Custom domains**
- **Wildcard certificate**
- **Public exposure**
- **Resource limits**
- **GitLab sign-in** and **Bitbucket sign-in**
- **Bot protection**
- **Image scanning**
- **Model Context Protocol**
- **Databases**
- **Anonymous usage reports**

Grafts can add sections to this page. A saved setting reaches every server replica within 30 seconds.

When an environment variable sets a field, the field is read-only and shows `Set by the environment`. Secret fields show `Unchanged` when a value is stored. Leave them blank to keep the value.

`SIGNUP_MODE` is not on this page. To change it, set the `signupMode` chart value to `open`, `invite_only`, or `closed`.

## Change settings that Instance admin cannot edit

Some settings are on the server or in your Helm values, so **Instance admin** cannot save them. **Instance admin** > **Networking** > **Addresses** and the last page of instance setup show what to change, in the form that matches how you installed Orchard. An instance that the installer manages has the `INSTALL_INGRESS_MODE` variable. Orchard treats any other instance as a Helm install.

On an installer host, `--apply` runs `sudo orchardctl update`, which also upgrades Orchard to the latest release. To make several changes and deploy once, leave out `--apply`, and run `sudo orchardctl update` after the last change.

On a Helm install, apply your values with your usual `helm upgrade` or GitOps process.

### Dashboard domain

The dashboard domain is where people sign in, and the address in the links that Orchard generates.

Before you change it, point the new name at this instance. In `public` mode, create an `A` record. In `tunnel` mode, add a public hostname to your tunnel. In `lan` mode, make sure the name resolves on your network.

<Tabs syncKey="installMethod">
<TabItem label="Script install">

```bash
sudo orchardctl hostname set orchard.example.com --apply
```

The command changes `ingress.host` and `FRONTEND_URL` together, and keeps the scheme and port that the instance serves on.

</TabItem>
<TabItem label="Helm">

Set both values. Keep the other entries in `server.env`. If a Secret sets `FRONTEND_URL`, change it there instead.

```yaml
ingress:
  host: orchard.example.com
server:
  env:
    - name: FRONTEND_URL
      value: https://orchard.example.com
```

</TabItem>
</Tabs>

The change has these effects:

- Everyone signs in again.
- Passkeys stop working, because they belong to the old name. Use a password or a one-time sign-in link.
- The GitHub App and any SSO provider keep the old URL until you update them.
- The old name stops answering. On an installer host, to keep it, run `sudo orchardctl hostname add <old-name> --apply`.
- The custom domains target does not change.

### Apps domain

Orchard gives a new app an address under the apps domain.

Before you change it, create a wildcard record, such as `*.apps.example.com`, that points at this instance. In `tunnel` mode, add the wildcard to your tunnel.

<Tabs syncKey="installMethod">
<TabItem label="Script install">

```bash
sudo orchardctl apps-domain set apps.example.com --apply
```

The command changes `gateway.http.appDomain` and `APP_DOMAIN` together. Do not set `APP_DOMAIN` alone. The chart uses `gateway.http.appDomain` to set the suffix for new apps, and that suffix takes precedence over `APP_DOMAIN`.

</TabItem>
<TabItem label="Helm">

Set the value. If you also set `APP_DOMAIN` or `tenant.wildcardDomains`, change them to match. `tenant.wildcardDomains` takes precedence for new apps.

```yaml
gateway:
  http:
    appDomain: apps.example.com
```

</TabItem>
</Tabs>

Only new apps use the new domain. Deployed apps keep their addresses, including after a redeploy, while DNS for the old name points at this instance. To move an app, add a domain to it.

### MCP hostname

The MCP hostname is where AI agents connect.

A name directly under the apps domain needs no DNS record of its own. For any other name, create a record first.

<Tabs syncKey="installMethod">
<TabItem label="Script install">

```bash
sudo orchardctl mcp enable mcp.example.com --apply
```

</TabItem>
<TabItem label="Helm">

Set both values. If a Secret sets `MCP_BASE_URL`, change it there too.

```yaml
mcp:
  url: https://mcp.example.com
  ingress:
    host: mcp.example.com
```

</TabItem>
</Tabs>

Agents must reconnect at the new URL.

### Certificate issuer email

This is the address where Let's Encrypt sends notices about your account. Certificates are not affected, and they issue and renew with no address.

<Tabs syncKey="installMethod">
<TabItem label="Script install">

```bash
sudo orchardctl letsencrypt-email set you@example.com
```

The command changes the `letsencrypt` ClusterIssuer directly, so you do not need `--apply`. To read the address, run `sudo orchardctl letsencrypt-email`. Only `public` mode uses Let's Encrypt.

</TabItem>
<TabItem label="Helm">

The chart has no value for this address, because it does not create the issuer. Set `spec.acme.email` on your ClusterIssuer, where you manage cert-manager. `tenant.certClusterIssuer` and `ingress.tls.issuerRef` name the issuer.

```yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt
spec:
  acme:
    email: you@example.com
```

</TabItem>
</Tabs>

### Pinned settings

**Instance admin** can edit these settings until a value pins them. The field then shows `Cannot be edited here` or `Set by the environment`.

<Tabs syncKey="installMethod">
<TabItem label="Script install">

| Setting | Change the pinned value | Edit it in Instance admin again |
| --- | --- | --- |
| Public IP | `sudo orchardctl public-ip set <ip> --apply` | `sudo orchardctl public-ip unset --apply` |
| Custom domains target | `sudo orchardctl env set INGRESS_CNAME <host> --apply` | `sudo orchardctl env unset INGRESS_CNAME --apply` |
| Resource limits | `sudo orchardctl env set INSTANCE_RESOURCE_LIMITS on --apply` | `sudo orchardctl env unset INSTANCE_RESOURCE_LIMITS --apply` |
| Any other field | `sudo orchardctl env set <NAME> <value> --apply` | `sudo orchardctl env unset <NAME> --apply` |

</TabItem>
<TabItem label="Helm">

| Setting | Value | Edit it in Instance admin again |
| --- | --- | --- |
| Public IP | `tenant.publicIp` | Remove the value. |
| Custom domains target | `INGRESS_CNAME` in `server.env` | Remove the entry. |
| Resource limits | `INSTANCE_RESOURCE_LIMITS` in `server.env` | Remove the entry. |
| Any other field | The variable in `server.env` | Remove the entry. |

</TabItem>
</Tabs>

For the name of each variable, refer to the [configuration reference](/reference/configuration/).

A change to the public IP does not move ports and databases that are already public. They stay on the old address until you turn public access off and on again. A change to the custom domains target does not affect domains that you already added, while their CNAME reaches this instance.

## Secrets

Store secrets in Kubernetes Secrets. Do not commit them to a values file in a repository. The installer generates the secrets it needs and writes them to `/etc/orchard/values.yaml`, which only root can read.

## Base domain

`BASE_DOMAIN` is the parent domain for organization vanity addresses and status pages, such as `acme.example.com`. It is independent of the dashboard host and the app domain. Each needs its own DNS records.

When `BASE_DOMAIN` is set, Orchard creates an Ingress and a certificate for each vanity address and status page. The following settings apply to these hosts:

| Setting                 | Purpose                                                                                               |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `PLATFORM_NAMESPACE`    | The namespace for the Ingress. The chart sets this to the release namespace.                          |
| `PLATFORM_SERVICE_NAME` | The Service that the Ingress points at. The chart sets this to `frontend`.                            |
| `PLATFORM_SERVICE_PORT` | The Service port. The chart sets this to the frontend port.                                           |
| `CERT_CLUSTER_ISSUER`   | The ClusterIssuer for the certificate. Set this with `tenant.certClusterIssuer`. The default is `letsencrypt-prod`. |

The chart does not set these values if you use `server.envFrom`. In that case, add them to your Secret. Without them, the server uses `default/leaf-frontend:3000`.

A vanity address sends visitors to the organization's SSO sign-in page. If the organization has no working SSO connection, visitors go to the default sign-in page. The dashboard host keeps working if it is a subdomain of `BASE_DOMAIN`.

Changing `BASE_DOMAIN` does not move existing hosts. Each host keeps its Ingress and certificate on the old domain, while the API reports the new one. To move a host:

1. Point DNS for the new domain at the cluster.
2. Clear the subdomain in the organization's settings.
3. Set the subdomain again.

## Resource limits

`INSTANCE_RESOURCE_LIMITS` turns resource limits `on` or `off` for the whole instance, and locks the setting in **Instance admin**. Unset, the choice in **Instance admin** applies. If nobody has chosen, limits are on. If you unset the variable, Orchard keeps the value that it locked. For more information, refer to [Turn resource limits on or off](/operate/resource-limits/).

## Database memory

`DATABASE_DEFAULT_MEMORY_MB` sets the memory request for a database that has no size of its own. The default is `1024` and the minimum is `512`. The installer lowers the value on a machine with about 8 GB of memory or less.

## App memory

`DEFAULT_APP_MEMORY_MB` sets the memory limit for an app that has no size of its own and no organization default. The default is `128`. The installer sets the value on a new install, based on the memory of the machine.

## Namespace floor

`TENANT_QUOTA_FLOOR_PODS`, `TENANT_QUOTA_FLOOR_SERVICES`, `TENANT_QUOTA_FLOOR_PVCS`, and `TENANT_QUOTA_FLOOR_STORAGE_BYTES` set the most that a project without a cap can create when limits are on. The installer sets high values on a new install, so that the floor does not stop a small instance.

## The What's new sheet

The dashboard shows each person the latest release notes once. The server reads the notes from a folder that holds `latest.json` and one Markdown file for each release.

| Setting                | Default                                |
| ---------------------- | -------------------------------------- |
| `UPDATES_URL`          | `https://assets.orchard.my/updates/ui` |
| `updates.url` in chart | Empty, which keeps the server default. |

A value in `server.env` takes precedence over `updates.url`.

To hide the sheet, run the following command:

```bash
sudo orchardctl config set updates.url off --apply
```

To publish your own notes, point the setting at your own folder. `latest.json` needs a `version`, such as `2.70.0`. It can also have `file`, `url`, and `publishedAt`. The default `file` is `<version>.md`. A note shows only when its version is at or below the running version of the dashboard.
