Deploy a GitHub repository to Orchard and connect a PostgreSQL database to it. At the end, your app runs on an HTTPS URL and reads its connection string from a variable.

## Prerequisites

- A running Orchard instance that you can sign in to. To set one up, refer to [Install](/start/install/).
- A GitHub repository that contains a Dockerfile or an app that Orchard can detect.
- For private repositories, a GitHub App on the instance. To create one, refer to [Connect a GitHub App](/operate/finishing-setup/#connect-a-github-app).
- For the CLI steps, the `orchard` CLI. To install it, refer to [CLI](/cli/).

## 1. Connect GitHub

Connect your GitHub account so that Orchard can list your repositories. You can skip this step for a public repository.

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

1. Open your account menu and select **Account settings**.
2. Go to **GitHub and Tailscale**.
3. In **GitHub**, select **Connect**.
4. Approve the request on GitHub.
5. In **Repository access**, select **Add account** and install the GitHub App on the account that owns your repository.

</TabItem>
<TabItem label="CLI">

1. Sign in to your instance:

   ```sh
   orchard auth login --api-url https://orchard.example.com
   ```

2. Link your GitHub account:

   ```sh
   orchard github link --open
   ```

3. Install the GitHub App on the account that owns your repository:

   ```sh
   orchard github install --open
   ```

</TabItem>
</Tabs>

## 2. Deploy the app

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

1. Open a project and select **New app**.
2. In **Start from scratch**, select **GitHub repo**.
3. In **Repository**, select your repository. For a public repository, paste `owner/repo` into the search field.
4. In **Branch**, select a branch.
5. In **Name**, enter a name for the app.
6. In **Networking**, confirm that the port matches the port your app listens on.
7. In **Reach**, select **Public link** for a URL that anyone can open. The default, **Private link**, requires people to sign in to Orchard.
8. Select **Deploy**.

Orchard opens a progress page with these steps: **Starting the builder**, **Cloning the repo**, **Building the image**, **Pushing the image**, and **Rolling out**. The build logs stream on the same page.

</TabItem>
<TabItem label="CLI">

1. In your project directory, link the directory to an Orchard project:

   ```sh
   orchard link
   ```

2. Create the app and wait for the first build:

   ```sh
   orchard deploy create --github owner/repo#main --name web --port 3000 --wait
   ```

The CLI generates a URL that requires people to sign in to Orchard. To make the URL public, refer to [Deployment protection](/deploy/protection/).

</TabItem>
</Tabs>

The app is live when its status is **Running**. Its URL appears in the header of the app page.

If the build fails, refer to [Builds](/deploy/builds/#troubleshoot-a-failed-build).

## 3. Create a database

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

1. Open the project and select **New app**.
2. In **Start from scratch**, select **PostgreSQL**.
3. In **Database name**, enter a name.
4. Select **Create database**.

</TabItem>
<TabItem label="CLI">

```sh
orchard db create --name appdb --wait
```

</TabItem>
</Tabs>

## 4. Connect the database to the app

Connect the database with a reference. A reference follows the database through a password rotation or a restore.

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

1. Open the app and go to **Variables**.
2. Add a variable named `DATABASE_URL`.
3. In the value field, select **Use a resource**, then select your database.
4. Select **Save**.

</TabItem>
<TabItem label="CLI">

```sh
orchard deploy bindings add <app-id> --database appdb
```

This command adds `DATABASE_URL` to the app.

</TabItem>
</Tabs>

Orchard restarts the app with the new variable.
